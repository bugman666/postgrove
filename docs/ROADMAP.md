# Postgrove 路线图

> 品牌暂用 **Postgrove**。能力面可对照 Gmail、cloud-mail、ydddp/mail-hub，**实现与 UI 原创**。  
> 全程非目标：聚合第三方临时邮箱渠道（不做 mail-hub 式多渠道临时邮，避开 AGPL 纠缠）。

---

## P0 — MVP（当前里程碑）

**目标**：自有域名边缘邮箱最小闭环。

| 能力 | 说明 |
|------|------|
| 入站 | Email Routing → Worker → D1 |
| 收件箱 | 列表 / 阅读 / 删除 |
| 新写发送 | 可插拔出站提供商 |
| 附件 | R2 + 上限 |
| 鉴权 | 主人 + 简易 admin |
| 多地址 | 同一域名下多个地址 |
| 回复 | **仅 UI 入口**（真链路 → P1） |

**不做**：真实回复/转发、草稿、文件夹、搜索、会话、临时邮箱、API 收件箱。

验收锚点：Issue #1 简报 · 测试 A–F（D4 = 仅入口）。

---

## P1 — 邮箱完整度（偏 Gmail 体验）

**目标**：日常邮箱够用。

- 真实回复 / 全部回复 / 转发  
- 草稿  
- 文件夹：收件箱 · 已发送 · 垃圾邮件 · 垃圾箱  
- 搜索（至少主题/发件人/正文基础）  
- 未读 · 星标  
- 基础会话串（同主题简易线程，不追求完整 Gmail 会话算法）

---

## P2 — 平台（偏 cloud-mail 能力面 · UI 原创）

**目标**：可给小团队/自托管运营用。

- 多用户 + RBAC + 配额  
- 收信推送或转发（如 Telegram / 外部邮箱）  
- 开放 REST（管理与邮件基础操作）  
- Turnstile / 滥用防护  
- 轻量管理统计（量级概览，非重型 BI）  
- i18n  
- 轻自定义品牌（站点名、logo、主色——非整站换肤市场）

---

## P3 — 开发者 API（吸收 mail-hub 思路 · 不全抄）

**目标**：自有域名上的可编程收件箱。

- 自有域名下的 API 收件箱  
- 长轮询取信 / 验证码类内容提取辅助  
- `+` 别名  
- API Key + 配额  

**明确非目标**

- 聚合第三方临时邮箱渠道 / 公共临时邮池  
- 复制 mail-hub 产品形态或许可证风险路径  

---

## 阶段原则

1. **先通邮，再完整，再平台，再 API**  
2. 每阶段可独立发布；不预支下一阶段数据模型到无法演进即可  
3. 公开 README 只承诺已交付阶段；路线图可链到本文
