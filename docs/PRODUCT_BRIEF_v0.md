# Postgrove 产品简报 v0.1

> 仓库：https://github.com/bugman666/postgrove · 里程碑：MVP · Issue #1  
> 品牌工作名 **Postgrove**（暂用，以后可改）。  
> 能力可对照 Gmail / cloud-mail / mail-hub 的**能力面**分阶段吸收；**产品 / 设计 / 文案 / UI 必须原创**，禁止照搬其界面、文案或品牌。  
> 非目标（全程）：聚合第三方临时邮箱渠道（避免成为 mail-hub 类克隆，并避开 AGPL 纠缠）。

---

## 1. 一句话定位

给**自有域名的个人与小团队**用的边缘邮箱：在 Cloudflare Workers 上开地址、收信、读信、写信、管附件——不养完整邮件服务器；功能按 P0→P3 分阶段完善。

## 2. 受众（优先级）

| 优先级 | 受众 | 他们要什么 |
|--------|------|------------|
| P0 | 个人自托管者 | `name@自己的域名` 收验证码 / 业务信，网页能读、能新写 |
| P0 | 小团队（2–10 人） | 多个角色地址 + 简单管理 |
| P1+ | 需要更完整邮箱体验的人 | 回复/转发、文件夹、搜索、会话 |
| P2+ | 多用户部署 / 运营者 | RBAC、配额、推送、统计、轻品牌 |
| P3 | 开发者 | 自有域名下的 API 收件箱、轮询取信 |
| 非目标 | 临时匿名邮箱聚合用户 | **不做**第三方临时邮箱渠道聚合 |

## 3. P0 MVP 核心路径（可验收）

1. **部署通邮**：绑域名 → Email Routing → Worker → 可登录  
2. **开地址**：域名下创建多个邮箱地址  
3. **收信**：列表出现 → 阅读 → 删除（含附件下载）  
4. **新写发送**：出站可插拔（如 Resend 等）  
5. **附件**：R2 + 体积上限；超限给人话提示  
6. **鉴权**：邮箱主人 + 简易 admin  
7. **回复入口（仅 UI）**：阅读页提供「回复」按钮/入口；**点击后进入预填写信或占位说明即可，不要求真实回复链路在 P0 可用**（真回复在 P1）

成功画面：**一次认真下午内，从空仓到网页读到第一封入站信，并能新写出站。**

## 4. 非目标（P0 明确不做）

- 真实回复 / 全部回复 / 转发链路（P1）  
- 草稿、文件夹、搜索、星标、会话串（P1）  
- 临时 / 匿名即抛邮箱；第三方临时邮箱聚合（全程不做）  
- 日历、通讯录、协作文档、完整桌面客户端替代  
- 复杂 RBAC / 多租户计费（P2）  
- 验证码识别大盘、重度换肤  

文档诚实：域名、反垃圾、出站提供商额度由部署者负责。

## 5. 信息架构

### P0 必现

```
登录
├── 收件箱（默认）
│   ├── 列表：未读 · 发件人 · 主题 · 时间
│   └── 阅读：正文 · 附件 · 删除 · 【回复入口】
├── 写信（新写）
├── 地址
└── 设置（账号 · 路由提示 · 附件上限 · 登出）
```

### P1+ 预留（导航可先占位，不绑死 P0 实现）

- 文件夹：收件箱 / 已发送 / 垃圾邮件 / 垃圾箱  
- 搜索框  
- 星标 / 未读筛选  
- 设置扩展（多用户、推送、API Key 等按阶段出现）

详见 `docs/ROADMAP.md`。

## 6. 语气

- 实用、短句、不吹牛、不卖惨  
- 公开文案不出现内部工具名  
- 错误：「发生了什么」+「你可以做什么」  
- 空收件箱：「还没有信。域名路由配好后，寄一封到你的地址试试。」  
- 回复入口未就绪时（若点占位）：「回复能力将在下一阶段开放；你仍可以新建写信。」
