# Postgrove 产品简报 v0（可验收草案）

> 工作名：Postgrove · 仓库：bugman666/postgrove · 状态：脚手架  
> 原则：能力可对齐同类 Cloudflare 邮箱开源项目；**UI / 文案 / 品牌必须原创**，不复用其视觉与语气。

## 1. 一句话定位

给自托管者与小团队的 **边缘邮箱**：在自有域名下开地址、收信、写信、管附件——跑在 Cloudflare Workers 上，不装完整邮件服务器。

## 2. 非目标（刻意不做）

- 不是企业套件（日历 / 通讯录 / 协作文档）
- 不是「临时邮箱即抛」产品（可后加，但不进 MVP 叙事）
- 不做「假企业级」承诺；路线图保持可见、诚实

## 3. 目标用户与核心场景

| 角色 | 痛点 | MVP 成功画面 |
|------|------|--------------|
| 个人自托管者 | 想要 `me@mydomain` 收验证码/业务信，又不想养 Postfix | 部署后 10 分钟内能在网页里读到第一封入站信 |
| 小团队运维 | 需要几个角色邮箱（support / billing）+ 基础管理 | 多地址、简单权限、附件可读可下 |
| 开源贡献者 | 想 fork 一个「面小、文档真」的邮箱项目 | README / 空状态 / 错误文案能直接讲清边界 |

## 4. 能力边界对照（仅范围，不抄产品）

可参考的能力面：多地址 · 收发 · 附件(R2) · 管理 · 人机验证 · 推送/转发 · 开放 API。

**Postgrove MVP 只吃前半段：**

1. 入站：Email Routing → Worker → D1  
2. Web 收件箱：列表 / 阅读 / 删除 · 响应式  
3. 出站：可插拔 SMTP/API（如 Resend）  
4. 附件：R2 + 体积上限  
5. 鉴权：邮箱主人 + 简易 admin  

推送、验证码识别、可视化大盘、重度个性化皮肤 → **路线图，不进 MVP 主叙事**。

## 5. 信息架构（MVP）

```
登录
├── 收件箱（默认）
│   ├── 列表（未读 / 发件人 / 主题 / 时间）
│   └── 阅读（正文 · 附件 · 删除 · 回复入口）
├── 写信（收件人 · 主题 · 正文 · 附件 · 发送状态）
├── 地址（我的邮箱地址列表 · 新建）
└── 设置 / 管理（账号 · 域名提示 · 配额/上限 · 登出）
```

空状态优先文案（原创语气）：「还没有信。域名路由配好后，寄一封到你的地址试试。」

## 6. 关键用户旅程（验收用）

1. **部署者**：按文档绑域名 → 开 Worker/D1/R2 → 路由通 → 登录后台  
2. **收信**：外部发信 → 列表出现 → 打开可读 → 附件可下  
3. **发信**：写一封 → 提供商接受 → 发送状态可见  
4. **失败可读**：鉴权失败 / 附件超限 / 未配出站 → 一句人话 + 下一步

## 7. 体验与视觉方向（token 草案）

- **气质**：冷静、林间感、偏工具；少装饰、多留白；「grove」= 安静的一片邮箱树，不是霓虹 SaaS  
- **配色（草案）**：墨绿主色 `#1B4332` · 浅纸底 `#F7F5F0` · 强调 `#2D6A4F` · 危险 `#9B2226` · 边框 `#D8D2C8`  
- **字体**：系统栈优先（界面）；等宽仅用于地址 / Message-ID  
- **布局**：桌面三栏可选（文件夹 | 列表 | 阅读）；手机单栏 + 底部主导航  
- **禁止**：照搬 Element 默认后台壳、紫蓝渐变登录页、emoji 堆砌标题

## 8. 文案语气

- 实用、短句、不卖惨不吹牛  
- 公开文案不出现内部工具名  
- 错误优先「发生了什么 + 你能做什么」

## 9. 待项目负责人拍板（再转用户）

2. 主域名 / demo 域名是否有计划

4. 首交付优先级：落地页语气 vs 线框说明 vs design token PR
